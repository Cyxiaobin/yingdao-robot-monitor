> **联调时间**：2026-11-16 17:10-17:20，公有云 `https://api.yingdao.com`，平台级凭证（`@platform` 后缀）。
> **结论**：鉴权 + 6 个只读接口全部跑通，`docs/字段对照表.md` 已按真实响应修正；`backend/app/mock_data.py` 已同步改成真实结构。

## 鉴权

| 项 | 实测值 |
|---|---|
| 接口 | `GET /oapi/token/v2/token/create?accessKeyId=&accessKeySecret=` |
| 返回 | `data.accessToken`（UUID）、`data.expiresIn = 7200` 秒 |
| 约定 | 后续接口 Header `Authorization: Bearer ${accessToken}` |
| 缓存策略 | 后端按 `expiresIn` 缓存，提前 300 秒刷新；未过期时影刀返回旧 token |
| 密钥获取 | 企业管理员登录 https://console.yingdao.com/user/login → 高级设置 → API KEY 管理 → 创建 API KEY（每个对接系统单独一对）；社区版不支持 |
| 凭证类型 | 本次使用平台级凭证（`accessKeyId` 带 `@platform`），日志类接口可正常调用 |

## 实测接口结构（与初始假设的差异）

| 接口 | 方法 | 请求体 | 响应层级 | 实测 |
|---|---|---|---|---|
| `token/v2/token/create` | GET | query 参数 | `data.{accessToken,expiresIn}` | ✅ |
| `dispatch/v2/client/list` | POST | `{page,size}` | **`data` 为数组** | ✅ 8 条 |
| `dispatch/v2/task/newest/list` | POST | `{size}` | **`data.pageDTO` + `data.result[]`** | ✅ 70 条（size=100） |
| `dispatch/v2/task/process/detail` | POST | `{taskUuid, robotClientUuid}` | `data.jobList[]` | ✅ 必须传**匹配的**机器人 uuid，否则空数组 |
| `dispatch/v2/job/query` | POST | `{jobUuid}` | `data` 对象 | ✅ |
| `dispatch/v2/job/log/search` | POST | `{jobUuid,page,size}` | `data.page` + `data.logs[]` | ✅ 13 条 |
| `dispatch/v2/job/stop` | POST | `{jobUuid}` | — | 后端已封装，**联调脚本刻意不调用**（写操作） |

**踩过的坑（已修）**：

1. `task/newest/list` 是 `data.result`，不是 `dataList` —— 原聚合器解析不到，真实模式看板「最近运行」会全空。
2. 运行终态是 `finish` / `error` / `stopped`，**不是** `success` / `fail`；`stopped` 归为异常。
3. 应用名是 `taskName`（或 `taskClients[0].currentRobotName`），不是 `robotName`。
4. 列表接口**没有** `startTime` / `endTime` / `screenshotUrl`；耗时用 `createTime → updateTime`（或 `sceneInstStartTime`），截图只能从 `process/detail` 的 `jobList[].screenshotUrl` 取。
5. `jobUuid ≠ taskUuid`：日志/详情链路必须 `newest/list → process/detail → jobUuid`。
6. `job/log/query` 是 **GET + requestId**，需先 `POST job/log/notify` 拿 requestId 再轮询；一步式改用 `POST /job/log/search`（body 带 jobUuid）。

## 新增接口字段（2026-11-17 真实凭证实测）

| 用途 | 接口 | 请求体 | 响应要点 |
|---|---|---|---|
| 查询已发布流程 | `POST /oapi/app/open/query/list` | `{page, size, appName?}` | `data` 是**数组**（`appId` / `appName` / `version` / `appStatus` / `publishTime` / `ownerName` / `ownerAccount` / `appType` / `supportParam` / `description`）；分页在**顶层 `page`**（total/size/page/pages）。实测 total=147 |
| 已发布判据 | 同上 | — | `publishTime` 非空 且 `appType=='app'` → 91 个。`appStatus` 恒为 `r`、`version` 恒有值，不能用来判发布；100 条样本里 40 条无 `publishTime` |
| 搜索 | 同上 | `appName` 支持模糊匹配 | 实测「退单」命中 3 个；代码另做 60 秒全量缓存 + 本地过滤，避免限频 |
| 启动应用 | `POST /oapi/dispatch/v2/job/start` | 必填 `robotUuid`（= 应用 `appId`）；可选 `accountName`（= `client/list` 的 `robotClientName`）、`robotClientGroupUuid`、`params[]`、`idempotentUuid` | `data.jobUuid` / `data.idempotentFlag` |
| 重试 | `POST /oapi/dispatch/v2/job/retry` | `{jobUuid}` | 仅 `{code:200, success:true}`，**无 data**；官方文档明确只对「异常 / 已停止」状态有效 |
| 机器人账号名 | `client/list` | — | `robotClientName`（如 `old5-1@demo`），作为 `job/start` 的 `accountName` |

**踩过的坑**：`/oapi/dispatch/v2/app/query/list`、`/oapi/dispatch/v2/app/list`、`/oapi/dispatch/v2/task/query/list`、`/oapi/dispatch/v2/robot/v2/query` 全部 404（正确的应用列表在 `/oapi/app/open/query/list`，不在 dispatch/v2 下）；`/oapi/dispatch/v2/task/list` 存在但强制要 `sourceUuid`，未采用。
**写操作未实测**：`job/start`、`job/retry` 只在代码里封装，测试全部用 MOCK 与不存在的 ID，绝不向生产环境发启动/重试请求。

## 已知限制与待确认

1. **概览口径**：`Aggregator.poll_once` 拉最近 50 条运行记录（实测 `pageDTO.total=72`）。若当日运行超过 50 次，今日数会被低估；后续可翻页或加大 `size`。
2. **回调入口**：影刀《启动应用》文档提到「控制台 - api 执行配置回调接口」，但**是否对本企业开放、回调体结构**仍需在控制台人工确认。当前实时性由 5 秒轮询承担，回调端点 `POST /api/callback` 已就绪待配。
3. ✅ **运行中态已捕获**（2026-11-17 08:31 补充观测）：`task/newest/list` 出现 `status: "running"`（如「总部004-银企直连-平安」，无 `updateTime`、耗时 0）。代码 `_RUN_RUNNING` 与前端 `RUN_STATUS_MAP` 已覆盖，显示「运行中」。机器人 `client/list` 的 status 仍只观测到 `idle` / `offline`。
4. **密钥安全**：`accessKeyId/Secret` 只存 `backend/.env`（已加入 `.gitignore`），不进代码/文档/小程序。该对凭证曾出现在聊天记录中，建议轮换。
